# A dumb Node CLI does the work; the agent does the judging

`preset-manager` is a zero-dependency Node CLI with automated tests plus a thin skill that calls it. The CLI applies presets, creates, updates and deletes them, and lists unassigned skills; the agent decides groupings and shows a proposal the person approves before anything is written. Writes are guarded: dry run by default, backup of `settings.json` and `CLAUDE.md` first, only touching preset blocks, skill switches and its own junctions, validation afterwards with restore on failure. A `--root` option points the tool at a fake config folder so tests never touch the real `~/.claude`. The one test-only switch in the shipped code is the environment variable `PRESET_MANAGER_FAULT=corrupt-settings`, which makes a write leave `settings.json` broken so the restore path is tested through the same command seam. A hook after `skills add` nudges the agent to propose a preset for newly installed skills. Chosen over a runbook the assistant follows, because the safety rules can only be guaranteed and tested in code.
